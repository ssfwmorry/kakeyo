# グラフライブラリ選定まとめ（Vue → React/Next.js 移行）

- **作成日**: 2026-09-21
- **対象**: 「かけよ」のグラフ機能を Vue アプリから React（Next.js）へ移行するにあたってのグラフライブラリ選定
- **UI 方針**: グラフ以外は Shadcn で独自実装。グラフは現状 Chart.js を使用しているが、あまり納得がいっていないため、より使いやすいものがあれば乗り換える。

---

## 結論

**shadcn/ui 公式のチャートコンポーネント（Recharts ベース）への移行を推奨**する。

理由の要点:
- **UI 方針と完全に一致**する。shadcn/ui のチャートは Recharts の上に薄いラッパを載せた「copy-and-own」コンポーネントで、他の Shadcn コンポーネントと同じ流儀・同じ Tailwind トークンで扱える。
- 現状使っている **円・棒・積み上げ棒・折れ線をすべてカバー**する。
- **Recharts は SVG レンダリング**で、React/Next.js との相性が良く、宣言的な JSX API で書けるため、命令的な Chart.js より React では扱いやすい。
- 「かけよ」のデータ量は月次・年次の集計値（数十〜数百点）で小規模なため、Recharts の弱点であるパフォーマンス（2000点超で描画が重くなる）は問題にならない。
- **無料・OSS**。

## 現状の実装と機能要件

### 使用ライブラリ（現状）

`package.json`:
- `chart.js`（^4.4.7）
- `vue-chartjs`（^5.3.2）
- `chartjs-adapter-dayjs-4`（^1.0.4） … 折れ線の時間軸アダプタ

### グラフ利用箇所と要件

| 種類 | コンポーネント / ページ | 用途 | 特徴的な要件 |
|---|---|---|---|
| **円グラフ (Pie)** | `components/SummaryPie.vue` | カテゴリ / 方法別の支出・収入割合 | カスタム背景色（カテゴリ色）、`responsive`、凡例 |
| **棒グラフ (Bar)** | `components/SummaryBar.vue` | 年間の月別収支 | 単色棒、凡例非表示 |
| **積み上げ棒グラフ (Stacked Bar)** | `components/SummaryBarType.vue` | 月別のカテゴリ / サブカテゴリ積み上げ | `scales.x/y.stacked: true`、独自凡例（`v-avatar` で色チップ表示） |
| **折れ線グラフ (Line)** | `pages/bank.vue` | 銀行残高の時系列推移 | 時間軸（`TimeScale` + dayjs アダプタ）、`fill`（エリア塗り）、`tension`、Y 軸フォーマッタ（万円単位）、積み上げ |

いずれも Chart.js + `vue-chartjs` で実装。データ整形（`convertShowData` 等）はロジックとして分離されており、**データ整形部分は移行後もほぼ流用可能**。

## 採用ライブラリ: shadcn/ui Chart（Recharts）

### 選定理由

1. **Shadcn 方針との一体化**
   - `pnpm dlx shadcn@latest add chart` でソースが自リポジトリに入る copy-and-own 型。
   - 色は CSS 変数（`var(--color-KEY)`）で管理でき、Tailwind / Shadcn のテーマトークンにそのまま乗る。
   - `ChartContainer` / `ChartTooltip` / `ChartTooltipContent` / `ChartLegend` / `ChartLegendContent` を必要な箇所だけ組み合わせる合成（composition）スタイル。

2. **必要なグラフ種を全てカバー**
   - Area / Bar / Line / Pie / Radar / Radial に対応。
   - **積み上げ棒**は Recharts の `<Bar stackId="...">` で表現可能。
   - **折れ線の時間軸**は `XAxis` の `tickFormatter` で日付フォーマット（`date-fns` 等）を行う。Chart.js のような専用時間アダプタ（`chartjs-adapter-dayjs-4`）は不要になる。
   - **エリア塗り**は `<Area>`、曲線は `type="monotone"` などで対応。

3. **React / Next.js との相性**
   - SVG レンダリングで SSR と親和。ただし内部でブラウザ API を使うため、**チャートを含むコンポーネントには `"use client"` が必要**。
   - 宣言的 JSX で、Chart.js の「register してオプションオブジェクトを組む」命令的スタイルより見通しが良い。

### 導入（想定）

```
pnpm dlx shadcn@latest add chart
# Recharts が peer として入る
```

---

## Chart.js から乗り換える理由（現状の不満点の解消）

- Chart.js は Canvas ベースかつ命令的で、`ChartJS.register(...)` によるモジュール登録やオプションオブジェクトの記述が冗長。React では「宣言的に書けない」ことが扱いにくさにつながりやすい。
- 独自凡例（`SummaryBarType.vue` の色チップ）などは、Recharts なら JSX コンポーネントとして自然に組める。
- 色管理を CSS 変数へ寄せられるため、Shadcn のテーマ（ダーク/ライト含む）と一貫させやすい。

---

## 代替案（今回は非採用）

### react-chartjs-2（Chart.js の React ラッパ）
- **移行コストは最小**（既存の Chart.js オプションをほぼそのまま持ち込める）。
- ただし「Chart.js に納得がいっていない」という前提と、Shadcn 方針との一体感の薄さから非採用。
- ※ どうしても移行工数を最優先する場合の保険的選択肢。

### Nivo
- D3 ベースで見た目の完成度が高く、アクセシビリティ（WCAG 2.1 AA）に強い。
- ただし Shadcn のテーマ統合という観点では shadcn/ui Chart に劣り、依存も重め。

### visx（Airbnb）
- D3 の低レベルプリミティブ集。最大の自由度が得られるが、プリミティブから組む必要があり工数が大きい。今回の用途（定型的な円/棒/折れ線）にはオーバースペック。

### ECharts / Chart.js（Canvas 系）
- 10万点超・リアルタイム描画向け。「かけよ」のデータ規模では利点が生きない。

## 移行時の注意点

- **`"use client"` の付与**: Recharts / shadcn Chart を使うコンポーネントはクライアントコンポーネントにする。
- **動的 import の検討**: グラフはバンドルが大きめなので、初期表示が重い画面では `next/dynamic`（`ssr: false`）での遅延読み込みを検討。
- **時間軸の置き換え**: `bank.vue` の `TimeScale` + `chartjs-adapter-dayjs-4` は、Recharts では `XAxis` の `tickFormatter` + `date-fns`（または dayjs）に置き換える。これに伴い `chartjs-adapter-dayjs-4` は不要。
- **データ整形の流用**: `convertShowData` 系のロジックは Recharts が期待する配列形式（`[{ label, value, ... }]`）へ最終整形するだけで再利用できる。Chart.js の `datasets` 形式から Recharts の「行オブジェクトの配列」形式への変換は必要。
- **積み上げ棒**: `stackId` を揃えることで実現。サブカテゴリ色は現状の `subTypeColors` を CSS 変数化して渡す。
- **レスポンシブ**: `ChartContainer` に `min-h-[...]` の指定が必要（shadcn Chart の仕様）。
