# カレンダーライブラリ選定まとめ（Vue → React/Next.js 移行）

- **作成日**: 2026-09-21
- **対象**: 「かけよ」のカレンダー機能を Vue アプリから React（Next.js）へ移行するにあたってのカレンダーライブラリ選定
- **UI 方針**: カレンダー以外は Shadcn で独自実装。カレンダーは独自実装が大変なため、ライブラリを採用する。

---

## 結論

カレンダー機能は React でも実現可能。**`@fullcalendar/react`（FullCalendar の React 版）への移行を推奨**する。

理由の要点:
- 現状すでに `@fullcalendar/vue3` を使用しており、**API・型・ロジックの大部分をそのまま流用できる**（移植リスクが最小）。
- 必要な機能をすべて**標準機能でカバー**できる。
- 使用中のプラグイン（`dayGrid` / `interaction`）は **MIT ライセンス（無料）**。

---

## 現状の実装と機能要件

対象ファイル:
- `kakeyo/pages/calendar.vue`
- `kakeyo/composables/useCalendarStore.ts`
- `kakeyo/utils/types/domains/calendar.ts`

現状は「単なる日付選択」ではなく、作り込まれたイベントカレンダー。移行先ライブラリには以下の機能が必須。

| 必須機能 | 現状の実装箇所 |
|---|---|
| 月グリッド表示（週数可変 `fixedWeekCount: false`） | `initialView: 'dayGridMonth'` |
| 日付セルへの独自コンテンツ表示（日ごとの収支金額） | `createCalendarEvents` の RECORD イベント |
| 複数日にまたがるバー表示（plan） | plan の start〜end |
| 背景イベント（祝日ハイライト） | `display: 'background'` |
| イベントの並び順制御 | `eventOrder: 'type,start,-duration,allDay,title'` |
| 日付クリック / イベントクリックのフック | `dateClick` / `eventClick` |
| 土日・祝日のセル色分け（CSS カスタム） | `<style>` の `:deep(...)` |
| プログラムからの月移動・スワイプ操作 | `getApi().gotoDate()`、`v-touch` |
| `extendedProps` へのドメインデータ格納 | `ExternalEvent` 型（planId, reminderId など） |

---

## 採用ライブラリ: `@fullcalendar/react`

### 選定理由

1. **移植性が圧倒的に高い**
   FullCalendar は Vue 版と React 版で API 設計が共通。`CalendarOptions` / `EventInput` / `dayGridPlugin` / `interactionPlugin` / `eventClick` / `dateClick` / `extendedProps` などがそのまま使える。
   - `utils/types/domains/calendar.ts` の型定義（`@fullcalendar/core` 由来）は流用可能。
   - `useCalendarStore` のイベント生成ロジック（`createCalendarEvents` 等）はほぼそのまま移植できる。

2. **要件を標準機能で全て満たす**
   - `dayCellContent` / `eventContent` の描画フックでセル・イベントを自由にカスタマイズ可能。
   - 背景イベント（`display: 'background'`）、複数日イベント、`eventOrder` すべて対応。

3. **ライセンスは MIT（無料）**
   使用中の `dayGrid` / `interaction` プラグインは無料枠。有償は Premium プラグイン（リソースビュー等）のみで、今回は不要。

### 導入パッケージ（想定）

```
npm install @fullcalendar/react @fullcalendar/core @fullcalendar/daygrid @fullcalendar/interaction
```

---

## Shadcn 方針との両立

- **カレンダー以外の UI は Shadcn で独自実装**、**カレンダーのみ FullCalendar** という切り分けが自然。
- FullCalendar は自前の DOM / CSS を持つが、Material UI のような密結合はない。現状同様に CSS で見た目を Shadcn / Tailwind のトークンへ寄せられる（現状も `:deep()` で細かく上書き済み）。

---

## 代替案（今回は非採用）

### react-big-calendar
- 機能自体は足りるが、色変更など基本操作にも独自ロジックが必要で、Vue 版 FullCalendar からの移植コストが高い。
- デフォルトが「週/日のタイムグリッド寄り」で、今回の「月グリッドのマスに金額表示」用途では作り込みが増える。

### ReUI Event Calendar（shadcn copy-and-own）
- UI 方針には最も合致し魅力的。ソースを自リポジトリに取り込む「copy-and-own」型。
- ただし独自エンジン実装で、背景イベントや「日セルに金額」といった細かな要件の実現性が読みにくく、Vue 版からの移植ではなく作り直しになる。
- **Shadcn で完全統一したい意向が強ければ将来的な有力候補**。

### その他
- react-datepicker / react-day-picker / shadcn/ui Calendar / react-calendar / MUI Date Calendar は、いずれも日付選択寄りでイベントカレンダー用途には不足。

---

## 移行時の注意点

- **ref の扱い**: Vue 版の `ref="fullCalendar"` + `getApi().gotoDate()` は、React 版では `useRef<FullCalendar>` + `ref.current.getApi()` に置き換える。
- **スワイプ操作**: `v-touch` は FullCalendar の機能ではないため、React 側で別途実装が必要（例: `react-swipeable`、または独自実装）。
- **CSS カスタム**: 現状 `:deep()` で行っているセル装飾（土日・祝日色、本日ハイライト、イベント枠線除去など）は、React 側では CSS Modules / グローバル CSS / Tailwind いずれかで同等の上書きを行う。
