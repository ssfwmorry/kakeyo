# T07 ドラッグ並べ替え基盤（dnd-kit・SortableList・reorder Action）

- 依存: T01。
- 原典: `project/SetType.dc.html` / `SetTypeEdit.dc.html` / `SetMethod.dc.html` / `SetPlanType.dc.html` / `SetPlanned.dc.html` の「編集」「並べ替え」状態（行末の 2 本線ハンドル 18px `--icon-muted`、`SetTypeEdit` のサブカテゴリは 32×44 の枠）。Main「並べ替え」。

## デザイン仕様（並べ替えの共通形）
- ヘッダー右のテキストボタン「編集」（または「並べ替え」）⇄「完了」で編集モードに入る。
- 編集モード中: 行末のシェブロンがハンドル（`IconGrip` 18px `--icon-muted`、`aria-hidden`）になり、**ドラッグで任意順に並べ替える**。「完了」で確定。
- 画面ごとの違い（T08 / T10 で適用）: 行頭の「−」バッジの有無、追加行の表示、行タップの可否、注記の文言。
- 並び順の意味: 入力画面・予定追加のカテゴリ候補の並び（`sort` 昇順）。

## 現状
- `src/components/form/swap-button.tsx`（旧 shadcn Button）で「下と入れ替え」。サーバは `swapTypeAction` / `swapSubTypeAction` / `swapMethodAction` / `swapPlanTypeAction` / `swapPlannedRecordAction`（2 行の `sort` 交換）のみ。ドラッグ用ライブラリ無し。

## やること
1. `@dnd-kit/core` `@dnd-kit/sortable` `@dnd-kit/utilities` を追加（pnpm）。
2. `src/v2/components/sortable-list.tsx`: `items: {id}[]`、`renderItem(item, { handleProps, isDragging })`、`onReorder(ids)`。縦方向のみ、ハンドルでドラッグ（`PointerSensor` + `KeyboardSensor`、`activationConstraint: { distance: 4 }`）、ドラッグ中は面を持ち上げる（影 `0 8px 24px rgba(22,25,26,.18)`）。`DragOverlay` は使わず `transform` で動かす（Base UI Drawer 内でも動くこと）。
3. `SortableHandle`（32×44 の枠、`IconGrip` 18px `--icon-muted`、`aria-label="並べ替え"`、`touch-action: none`）。
4. **任意順の Action と service**（それぞれ `features/<feature>/actions.ts` に追加。デモも `features/demo/server/queries/*` に同名で no-op）:
   - `reorderTypeAction(ids: Id[])` → `service.reorderTypes(session, ids)`: 全 id が scope 内かつ同一バケット（isPay + pairId）であることを検証（`count === ids.length`）、そのバケットの既存 `sort` 値を昇順に取り、新しい順に再割当てして 1 トランザクションで更新（`sort` は UK でないので衝突しない）。
   - `reorderSubTypeAction(typeId, ids)`（バケット = typeId）、`reorderMethodAction(ids)`（isPay(null 含む) + pairId）、`reorderPlanTypeAction(ids)`（pairId）、`reorderPlannedRecordAction(ids)`（isPair + owner）。
   - スキーマは `z.object({ ids: z.array(idSchema).min(1) })`（`schemas.ts` に追加）。戻りは `FormActionResult`、成功トースト `L.snackbar.updated`「変更しました」（「入れ替えました」ではない）。再検証は `/v2/setting`（layout）と旧 `/setting`。
5. クライアント側の楽観更新: `onReorder` で並びを state に反映してから Action を呼び、失敗時は元に戻してエラートースト。「完了」を押した時点でまとめて送るのではなく、**ドロップごとに送る**（デザインは「完了」で確定だが、送信タイミングは実装判断。ドロップごとで可）。
6. 既存の `swap*Action` と `SwapButton` は v2 から参照しなくなる（旧画面は使い続けるので削除しない）。
7. 単体テスト: 再割当ての純関数（`domain/reorder.ts`: `assignSorts(existingSorts, orderedIds)`）をテスト。
