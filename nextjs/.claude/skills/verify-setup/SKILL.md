# verify-setup — 動作確認用スキル

このスキルは kakeyo(nextjs)における Claude の動作環境を確認するためのものです。
次の3つの動作を順に実行し、それぞれが正しく機能するかを目視で確認します。

1. **コードレビュー**(`/review` 相当)
2. **コード簡素化**(`/simplify` 相当)
3. **Playwright による画面スクリーンショット確認**

> このスキルは既存のグローバルスキル(`/code-review` / `/simplify`)には依存せず、
> kakeyo 専用の簡易ロジックを自前で実行します。

---

## 前提

- 作業ディレクトリ: `kakeyo/nextjs/`
- パッケージマネージャ: `pnpm`
- Playwright MCP は `mico-eng-basic` プラグイン提供の `playwright` サーバーを使う
  (ツール未登録ならセッション再起動で反映される)
- 画面確認・DB書き込みのルールは `AGENTS.md` に従う
  - public スキーマへの書き込みは必ずユーザーの許可を得る
  - 書き込み系の確認は**デモログイン**で行う(実DBに副作用を与えない)

---

## 実行手順

引数で対象を絞れます(例: `/verify-setup review` のように特定ステップのみ)。
引数がなければ **1 → 2 → 3 の全ステップ**を順に実行します。

各ステップの開始・終了時に、何を実行しているかを1行で報告してください。

### ステップ1: コードレビュー(`/review` 相当)

現在の差分を対象に、簡易的なコードレビューを行います。

1. 対象差分を取得する。
   - git リポジトリなら `git diff` と `git diff --cached` を確認する。
   - 差分がなければ、直近で変更されたファイルや `src/` 配下の主要ファイルを対象にする。
2. 変更内容を読み、次の観点で**確実性の高い指摘のみ**を挙げる。
   - 明確なバグ・不具合(nullアクセス、型不整合、境界条件など)
   - 明らかな再利用漏れ・重複
   - Next.js / Supabase の規約違反(`AGENTS.md`・`node_modules/next/dist/docs/` 参照)
3. 指摘は `file_path:line` 形式で簡潔に列挙する。指摘がなければ「指摘なし」と明記する。
4. **この段階ではコードを変更しない**(レビューのみ)。

> 目的は「レビュー動作が機能するか」の確認なので、深追いは不要。
> 差分が空の場合も、その旨を報告してステップ成功とみなす。

### ステップ2: コード簡素化(`/simplify` 相当)

現在の差分を対象に、**品質改善のみ**(バグ探索はしない)を行います。

1. ステップ1と同じ差分を対象にする。
2. 次の観点で簡素化できる箇所を探す。
   - 再利用(既存ユーティリティ・コンポーネントの活用)
   - 冗長なロジックの簡素化
   - 非効率な処理の改善
   - 抽象度(altitude)の調整
3. 改善が妥当であれば**実際に修正を適用**する。
4. 修正後は最低限の検証を行う。
   - `pnpm check`(biome)/ `pnpm check:type`(tsc)を実行し、壊していないことを確認する。
5. 変更点を要約して報告する。改善余地がなければ「変更なし」と明記する。

### ステップ3: Playwright による画面スクリーンショット確認

`AGENTS.md` の「画面の動作確認」ルールに従い、実際に画面を撮って目視確認します。

1. **アプリ起動**: `pnpm build && pnpm start` で本番ビルドを立ち上げ、`http://localhost:3000` を用意する。
   (起動はバックグラウンドで行い、起動完了を待ってから次へ進む)
2. **ログイン画面の撮影**: Playwright MCP でトップ / `/login` を開き、スクショを撮る。
3. **認証必須画面の撮影**(任意): `(private)` 配下(bank / setting / calendar 等)を撮る場合は、
   Playwright MCP で**デモログインボタンをクリック → 遷移 → スクショ**の順に行う。
   単純な headless スクショはログイン導線を辿れず login 画面で止まるため不可。
4. **保存先**: スクショは `nextjs/.screenshots/` に「連番＋画面名」で保存する
   (例 `01-login.png` / `02-bank.png`)。`.screenshots/` は `.gitignore` 済み。
5. **目視確認**: 保存した画像を **Read で開いて自分でも確認**する
   (HTTP ステータスや HTML だけで済ませない)。表示崩れ・文言・データ表示をチェックする。
6. 確認後、不要になった一時ファイルは `.screenshots/` を削除してよい。

> Playwright MCP のツールが使えない場合は、その旨を報告し「MCP未登録」としてステップを失敗扱いにする
> (セッション再起動で反映される旨も伝える)。

---

## 完了報告

全ステップ実行後、各ステップの結果を次の形式でまとめて報告してください。

- **ステップ1(review)**: 成功 / 失敗 — 概要(指摘件数など)
- **ステップ2(simplify)**: 成功 / 失敗 — 概要(変更有無)
- **ステップ3(screenshot)**: 成功 / 失敗 — 撮影画面と目視確認の結果

いずれかが失敗した場合は、原因(差分なし / MCP未登録 / ビルド失敗など)を明記してください。
